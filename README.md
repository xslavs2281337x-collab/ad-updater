# AD Updater

Python-скрипт для пакетного обновления атрибутов пользователей Microsoft Active Directory на основе CSV-файла.

Скрипт подключается к AD по **LDAPS (порт 636)** с использованием **Kerberos**, находит сотрудников, сравнивает текущие значения с данными CSV и отправляет на изменение только отличающиеся атрибуты.

## Возможности

- Поиск сотрудника по `sAMAccountName` (колонка `ACCOUNT`).
- Обновление `displayName`, `company`, `title` и `department`.
- Поиск руководителя по `displayName` (ФИО из колонки `manager`) и обновление атрибута `manager` по DN найденного объекта.
- Пропуск записи, если сотрудник или руководитель не найден однозначно.
- Пропуск обновления, когда отличий нет.
- Запись результатов и ошибок в `updater.log`.

## Формат CSV

CSV-файл должен иметь разделитель **`;`** и заголовки с **точным совпадением регистра**:

```csv
ACCOUNT;displayName;company;title;department;manager
ivanov;Иванов Иван Иванович;Пример организации;Инженер;ИТ;Петров Пётр Петрович
```

- `ACCOUNT` — логин сотрудника в AD.
- `manager` — ФИО руководителя, соответствующее его `displayName` в AD.
- Остальные столбцы — новые значения атрибутов пользователя.
- Пустые значения обычных атрибутов не обновляются. При пустом `ACCOUNT` запись пропускается; если руководитель не найден однозначно, запись также пропускается.
- Значение `department` ограничивается 64 символами. Проверьте допустимость сокращения данных до запуска.

В репозитории рекомендуется хранить только пример CSV с вымышленными данными. Реальный файл с данными сотрудников не публикуйте.

## Требования

- Windows с доступом к контроллеру домена и действующим контекстом Kerberos.
- Python **3.14.7** — версия, указанная для текущего окружения проекта.
- Зависимости проекта, в том числе `ldap3` и `python-dotenv` (устанавливаются из `requirements.txt`, если файл подготовлен).
- Доступ к LDAPS на порту 636 и доверенный сертификат сервера.
- Учётная запись с необходимыми разрешениями AD для изменяемых атрибутов.

Для адреса сервера используется переменная окружения `AD_SERVER`. Например, в локальном файле `.env`:

```dotenv
AD_SERVER=dc.example.internal
```

Файл `.env` нельзя добавлять в публичный репозиторий. В рабочем окружении используется внутренний сервер `dc-2-ca`.

## Запуск в PowerShell

Откройте PowerShell в директории проекта.

**1. Создайте виртуальное окружение, если его ещё нет:**

```powershell
py -m venv .venv
```

**2. Активируйте окружение:**

```powershell
.\.venv\Scripts\Activate.ps1
```

**3. Установите зависимости (при наличии `requirements.txt`):**

```powershell
python -m pip install -r requirements.txt
```

**4. Запустите скрипт:**

```powershell
python main.py
```

При запуске можно указать путь к CSV. Если просто нажать Enter, используется `users.csv` в текущей рабочей директории.

Без активации виртуального окружения запустить программу можно так:

```powershell
.\.venv\Scripts\python.exe main.py
```

> **Осторожно:** при `read_only=False` скрипт может изменять реальные учётные записи AD. Перед массовым запуском проверьте входной CSV и протестируйте работу на нескольких тестовых пользователях.

## Журналирование

События и ошибки записываются в файл `updater.log` **в текущей рабочей директории**. Путь зависит от того, откуда запускается скрипт.

## Файлы, исключаемые из Git

В `.gitignore` рекомендуется добавить:

```gitignore
.venv/
.env
users.csv
*.log
__pycache__/
*.pyc
```

Не публикуйте реальные ФИО, сведения о сотрудниках, внутренние адреса и параметры доступа без разрешения организации.
